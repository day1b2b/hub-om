## OM 변경 (`om-change`)

기획서: [specs/om-change.spec.md](om-change.spec.md)

| 규칙 | `PATCH /api/om-request/assign` | `POST /api/operations/[operationId]/drive-import/apply` | `PATCH /api/admin/database/cell` | 공통 테스트 |
|---|---|---|---|---|
| **R1** OM을 바꾸면 업무요청 담당자와 연결된 운영 회차 OM이 같은 값이 된다. | ✅ | ✅ | 🟡 | 1/1 통과 |
| **R2** 새 OM이 정해지면 Slack 업무요청 접수 스레드에 배정 댓글을 단다. 스레드 정보가 없으면 웹훅으로 단독 메시지를 보낸다. | ✅ | ✅ | 🟡 | 2/2 통과 |
| **R3** 같은 담당자로 다시 저장하거나, 미배정 값(빈 값·배정필요 등)으로 바꾸면 Slack 알림을 보내지 않는다. | ✅ | ✅ | ✅ |  |
| **R4** Slack 알림이 실패해도 저장한 OM 변경은 되돌리지 않는다. | ✅ | ✅ | ✅ |  |
| **R5** 권한이 없는 사용자는 OM을 바꿀 수 없고, 아무것도 바뀌지 않는다. | ✅ | ✅ | ✅ |  |
| **R6** OM 변경 요청은 활동 기록에 남는다. | ✅ | ✅ | ✅ |  |

- 🟡 **R1 @ `PATCH /api/admin/database/cell`** — 관리자 DB 화면에서 OM 칸을 고치면 업무요청 담당자가 따라 바뀌지 않는다. 2026-10-12 기획 확인: 맞춰야 함. 후속 작업으로 고친다.
- 🟡 **R2 @ `PATCH /api/admin/database/cell`** — 관리자 DB 화면에서 OM 칸을 고치면 Slack 배정 알림이 가지 않는다. 2026-10-12 기획 확인: 가야 함. 후속 작업으로 고친다.

## 회차 삭제 (`operation-delete`)

기획서: [specs/operation-delete.spec.md](operation-delete.spec.md)

| 규칙 | `DELETE /api/operations/[operationId]` | `DELETE /api/admin/courses/[courseId]` |
|---|---|---|
| **R1** 회차는 표시 삭제만 한다. 실제 데이터는 지우지 않고 삭제한 사람을 남긴다. | ✅ | ✅ |
| **R2** 삭제한 회차에 연결된 Google Calendar 일정을 지운다. | ✅ | ✅ |
| **R3** Calendar 일정 삭제가 실패해도 회차 삭제는 되돌리지 않고, 화면에 "일정 정리 대기"를 알린다. | 🟡 | ✅ |
| **R4** 이미 삭제된 회차를 다시 삭제하면 남아 있는 Calendar 일정 정리를 다시 시도한다. | ✅ | ✅ |
| **R5** 정리를 다시 시도할 때, 그 사이 복원된 회차의 일정은 지우지 않는다. | ✅ | ✅ |
| **R6** 권한이 없는 사용자는 삭제할 수 없고, 아무것도 바뀌지 않는다. | ✅ | ✅ |
| **R7** 삭제 요청은 활동 기록에 남는다. | ✅ | ✅ |
| **R8** 과정의 마지막 남은 회차와 1회차는 회차 단위로 지울 수 없다. | ✅ | ➖ |

- ➖ **R8 @ `DELETE /api/admin/courses/[courseId]`** — 과정 전체를 지우는 입구라 "마지막 회차·1회차 보호"가 의미 없다.
- 🟡 **R3 @ `DELETE /api/operations/[operationId]`** — 회차 하나를 지울 때 Calendar 일정 삭제가 실패해도 화면에는 "삭제됨"만 보이고 "일정 정리 대기"를 알리지 않는다(같은 회차를 다시 지우면 정리는 재시도됨). 2026-10-12 기획 확인: 알려야 함. 후속 작업으로 고친다.
