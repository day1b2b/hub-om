# 자동 보안 검사 (Security CI Gate)

hub-om은 개인정보(코치·매니저 이름, 일정, 이메일 논의 내역 등)를 다루므로,
**코드 변경(PR)이 올라올 때마다 GitHub이 자동으로 보안 검사**를 돌립니다.
사람 기억에 의존하지 않고, 문제가 있는 코드가 합쳐지기 전에 걸러내는 것이 목적입니다.

설정 위치: [`.github/workflows/security.yml`](../../.github/workflows/security.yml)

## 무엇을 검사하나

| 검사 | 하는 일 | 결과 |
| --- | --- | --- |
| 시크릿 스캔 | 비밀번호·API 키·토큰이 코드에 실수로 섞였는지 (gitleaks) | ❌ **걸리면 머지 차단** |
| 의존성 취약점 | 사용하는 라이브러리에 알려진 심각(critical) 취약점이 있는지 (npm audit) | ❌ critical 차단 / 그 외 경고 |
| 코드 정적 분석 | 위험한 코드 패턴 (semgrep) | ⚠️ 참고용 (차단 안 함) |
| API 권한 커버리지 | 새 API에 인증/권한 확인이 빠졌는지 | ⚠️ 참고용 (차단 안 함) |
| 로그 개인정보 노출 | 이름·이메일 등을 로그에 찍는 코드가 있는지 | ⚠️ 참고용 (차단 안 함) |

시작 단계에서는 **시크릿과 심각 취약점만 차단**하고 나머지는 경고로 둡니다.
제작 일정을 막지 않으면서 눈에는 보이게 하려는 의도입니다.
팀이 익숙해지면 차단 범위를 넓힐 수 있습니다.

## 결과는 어디서 보나

PR 화면의 **Checks 탭**과 각 검사의 **Summary**에 표로 나옵니다.
`⚠️ 참고용` 항목은 PR의 **Files changed**에 인라인 경고로도 표시됩니다.

## 로컬에서 직접 돌려보기

커스텀 점검 2개는 별도 설치 없이 Node로 바로 실행됩니다.

```bash
# API 라우트별 인증/권한 확인 여부
node scripts/security/check-api-auth.mjs

# 로그에 개인정보가 찍히는 코드 탐지
node scripts/security/check-pii-logs.mjs
```

## 주의: 이 검사가 '전부'는 아닙니다

자동 검사는 **앞으로 들어오는 코드**를 거르는 장치입니다. 다음은 자동으로 잡히지 않으므로
별도의 정기 점검·개발이 필요합니다.

- **이미 작성된 코드의 권한 구멍** → 오픈 전 1회 정밀 점검 대상
- **접속기록(감사 로그)** → "누가 누구의 개인정보를 조회·다운로드했는지" 남기는 기능은
  아직 없음. 개인정보보호법상 필요하므로 별도 개발 필요
- **서버/인프라(방화벽·DB 노출·백업)** → 서버 관리 권한 영역, 담당 협의 필요
