명시 주입 구분:
- batch1/batch2: 두번째 DELETE 자리에서 실제PG invalid integer CAST를 실행한다.
  첫번째 DELETE는 원본SQL그대로 실행되고 서버가 transaction을 abort한다.
  자연 발생 PG장애 또는 Mongo transient/commit ACK 증거로 주장하지 않는다.
- close: 실제 Pool.end와 socketclose 관찰을 마친 뒤 synthetic Error를 throw한다.
  실제 연결정리 실패 재현이 아닌 close rejection 제어흐름 주입이다.
  원본처럼 summary가 이미 출력되며 exit1, current stderr는 ACTIVITY_PRUNE_FAILED.
- original 의도적 오류는 원래 uncaught traceback일 수 있어 rawstderr 비출력/비보존,
  bounded memory+hash만 보고. current 원문오류/URI/키/PII 출력은 거부한다.
