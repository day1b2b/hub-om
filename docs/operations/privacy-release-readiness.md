# 개인정보 암호화 통합 배포 준비

## 현재 판정

2026-09-21 통합 변경은 서버 개인정보 암호화, 로그인 기반 브라우저 초안, 작성자 미확정 옛 초안 격리 및 배정 확인을 포함한다. **키만 설정한 뒤 앱을 먼저 배포하면 안 된다.** 기존 평문 DB를 읽지 못하거나 검색 해시가 없는 데이터가 조회에서 빠질 수 있다.

기존 PR #599에 통합 변경과 검증 결과를 반영하되, 운영 전환 조건과 데이터/기술 책임자 검토가 확인되기 전에는 초안 상태를 유지한다. 기본 통합 대상은 dev이며 main 배포는 별도 전환 순서를 따른다. Coolify의 실제 배포 브랜치·자동배포·현재 키 설정은 아직 확인하지 않았다. GitHub deployment 기록이 비어 있다는 사실은 자동배포가 없다는 증거가 아니다.

## 운영자가 준비할 것

1. Coolify 대상 앱과 배포 브랜치, 자동배포 여부를 확인한다.
2. 최근 운영 DB 백업과 복원 가능 여부, 로컬 파일 저장소 사용 여부를 확인한다.
3. 아래 비밀값을 서버 런타임 환경변수로 설정하고 별도 보안 저장소에 백업한다. 실제 값을 대화·Git·로그에 올리지 않는다. 기존 값이 있다면 새 값으로 덮어쓰지 않는다.
4. 앱과 예약·적재 작업을 멈출 전환 시간을 정한다. 중단 후 [서버 전환 절차](personal-data-encryption.md)의 migration, 사전 점검, 백필, enforce 검증 및 해당 로컬 파일 전환을 실행한다.
5. 새 앱의 조회·검색·인증·저장·첨부·초안 복구를 확인하고 업무를 재개한다. 기존 브라우저 자료는 각 사용자 브라우저에서 [옛 초안 전환 절차](legacy-draft-quarantine.md)를 진행한다.

## 설정 목록

| 용도 | 환경변수 | 값 |
| --- | --- | --- |
| 서버 개인정보 | `PII_ENCRYPTION_KEYS` | 키 ID에서 독립 난수 32바이트 base64 키로 매핑한 JSON |
| 서버 활성 키 | `PII_ACTIVE_KEY_ID` | 위 JSON에 존재하는 ID |
| 개인정보 검색 | `PII_INDEX_KEY` | 별도 독립 난수 32바이트 base64 키 |
| 정상 브라우저 초안 | `BROWSER_DRAFT_MASTER_KEYS` | 별도 독립 키의 ID→base64 JSON |
| 초안 활성 키 | `BROWSER_DRAFT_ACTIVE_KEY_ID` | 위 JSON에 존재하는 ID |
| 초안 계정 분리 | `BROWSER_DRAFT_OWNER_KEY` | 별도 독립 난수 32바이트 base64 키. 운영 후 값 유지 |
| 옛 초안 격리 | `BROWSER_DRAFT_QUARANTINE_KEYS` | 별도 독립 키의 ID→base64 JSON |
| 격리 활성 키 | `BROWSER_DRAFT_QUARANTINE_ACTIVE_KEY_ID` | 위 JSON에 존재하는 ID |
| 공개 앱 주소 | `BROWSER_DRAFT_APP_ORIGIN` | 실제 공개 HTTPS origin. 예: `https://app.example.invalid` |
| 평문 읽기 | `PII_ALLOW_PLAINTEXT_READS` | 정상 서비스에서는 `false` |

처음 설정한다면 독립 비밀키는 총 다섯 개다. 활성 ID와 공개 주소는 비밀키가 아니다. 기존 AUTH_SECRET이나 서로 다른 용도의 키를 재사용하지 않는다. 키 생성은 승인된 비밀 관리 환경에서 수행한다. 이 문서 작성 중 실제 키를 생성하거나 운영 환경에 주입하지 않았다.

`RUN_DB_MIGRATIONS=true`는 스키마 migration만 실행한다. 개인정보 백필·검색 해시 생성·전수 검증을 대신하지 않는다. 백업 확인 및 승인 범위 없이 켜지 않는다. MongoDB 이전 실행은 이번 PostgreSQL 암호화 전환에 포함하지 않는다.

## 아직 실행하지 않은 것

- 운영 DB·파일의 암호화 변환과 실제 키 설정.
- 실제 Coolify/OAuth 환경에서의 배포 검증.
- 각 실제 사용자 브라우저의 옛 초안 전환.
- 데이터/기술 책임자 검토 확인.

DB 변경 승인은 [DB 안전 규칙](db-write-safety.md)을 따른다. 로컬 코드 검토와 합성 검증은 운영 백업·복원 확인을 대신하지 않는다.

## 배포 준비 검증 기록

2026-09-21: 독립 PostgreSQL 18 임시 클러스터의 빈 DB에 migration 44개를 파일 순서대로 적용했다(`psql -X -v ON_ERROR_STOP=1`). 활동 로그·과정명 복구·동시 잠금·PII 전환 검사 4건, 하위 검사 포함 22개가 통과했다. 기존 55439 서비스는 건드리지 않고 55449를 사용했으며 PII 테스트 임시 복사본의 포트 guard와 import 경로만 조정했다. 최초 임시 import 오류는 fixture 수정 후 재실행해 통과했다. 실제 환경 파일이나 운영 DB는 사용하지 않았고 임시 클러스터는 종료했다.

배포 준비 검토에서 무관한 storage 이벤트가 다른 탭의 등록 snapshot을 불러오는 경로를 발견해 관련 legacy 키 이벤트로 제한했다. 회귀 테스트는 현재 입력 유지와 저장 시 CAS 충돌에 의한 POST 차단을 확인한다. 최종 일반 테스트 703개 통과, DB 환경 없는 기본 실행의 4개 skip은 위 별도 DB 검사에서 확인했다. Prisma schema 검증·타입 검사 및 변경 파일 lint가 통과했다. 전체 lint는 오류 0개/기존 경고 7개였으며 앞선 통합 build도 통과했다. GitHub CI로 최종 커밋을 다시 검증한다.
