# Google Drive 운영 상세 보강 기준

이 문서는 운영 상세페이지에서 Google Drive 자료를 찾아 표준 운영 필드 후보로 바꾸는 기준을 정리합니다.
실제 고객사명, 담당자명, 링크, 금액, 파일명 원문 예시는 저장소에 남기지 않습니다.

## 목적

운영 과정의 가장 풍부한 정보는 Drive 과정 폴더 안의 싱크업 문서, 강의관리 시트, 만족도 응답, 결과보고서에 흩어져 있습니다.
hub-om은 이 자료를 직접 덮어쓰지 않고, 상세페이지에서 검토 가능한 후보로 보여준 뒤 사용자가 선택한 항목만 반영합니다.

## 현재 구현 상태

현재 구현된 범위:

- 사용자가 상세페이지에 Drive 폴더 URL을 입력합니다.
- 상세페이지에서 기업명/과정명/기간 기준으로 Drive 폴더 후보를 검색합니다.
- 후보 폴더는 기업명, 과정명 토큰, 기간 월 정보, 소유자 담당자 일치 여부를 기준으로 점수화합니다.
- 사용자가 후보 폴더를 선택하면 기존 Drive scan/apply 흐름으로 이어집니다.
- 기존 데이터에 Drive URL 대신 폴더명 또는 파일명이 들어온 경우에는 Drive에서 같은 이름의 폴더/파일을 검색합니다.
- 파일명으로 찾은 경우에도 부모 폴더명이 과정명과 충분히 맞을 때만 과정 폴더로 인정합니다.
- 폴더 하위 파일을 제한 깊이로 탐색합니다.
- Google Sheets, Google Docs, Google Slides, Office `.xlsx`의 텍스트 후보를 읽습니다.
- `★NEW TEMPLATE`, `template`, `템플릿` 파일은 실제 운영자료 후보에서 제외하지만, 템플릿 파일만 있다는 이유로 폴더 후보 점수를 낮추지는 않습니다.
- 싱크업/준비 문서, 강의관리 시트, 만족도/설문 응답, 결과보고서, 패들렛 링크 후보를 만듭니다.
- 추출 후보는 상세페이지 검토 모달에서 선택 적용합니다.
- 전체 검색/조회 드라이런 결과는 `drive_import_runs`, `drive_import_results`에 저장할 수 있습니다.

아직 구현되지 않은 범위:

- 후보 폴더의 하위 폴더를 검색 단계에서 추가 확장 평가합니다.
- 폴더 검색 결과를 운영 건별로 캐시하거나 저장해 반복 검색 비용을 줄입니다.
- 선택된 폴더와 적용 결과를 import run 형태로 이력화합니다.
- Drive 조회 이력 결과를 운영 상세 화면에서 직접 탐색하는 UI를 제공합니다.

## 폴더 매칭 기준

Drive 폴더명은 대체로 아래 구조를 따릅니다.

```text
YYMM~YYMM_기업명_과정명
YYMM_기업명_과정명
YYMM-YY_기업명_과정명
```

실제 매칭에서는 아래 신호를 함께 봅니다.

- 기업명이 폴더명에 포함됩니다.
- 과정명 핵심 토큰이 폴더명에 포함됩니다.
- 운영 시작/종료월이 폴더명의 월 범위와 겹칩니다.
- 하위 폴더가 실제 차수 폴더일 수 있으므로 2단계 이상 탐색이 필요합니다.
- 폴더 소유자가 운영 건의 OM 또는 LD와 일치하면 신뢰도를 올립니다.

폴더명만으로 확정하지 않습니다. 같은 기업의 여러 과정, 같은 과정의 여러 차수, 연간 위탁교육 폴더가 섞일 수 있기 때문입니다.
단, 운영 건의 기업명이 있는 경우 기업명이 맞지 않는 폴더는 낮은 점수와 별도 표시로 검토 후보에 남깁니다.

Drive URL 대신 파일명이 저장된 기존 데이터도 있습니다.
이 경우 파일명을 직접 검색할 수 있지만, 아래 조건을 모두 만족해야 부모 폴더를 과정 폴더로 봅니다.

- 파일명 자체가 입력값과 충분히 유사합니다.
- 파일명에 기업명/기간뿐 아니라 과정명 고유 토큰이 포함됩니다.
- 부모 폴더명에도 과정명 고유 토큰이 포함됩니다.
- `강의 관리 시트`, `만족도`, `설문`, `응답`, `결과보고`처럼 여러 과정 파일을 모아둔 공용 폴더는 과정 폴더로 인정하지 않습니다.

## 문서 우선순위

후보 추출 시 우선 읽을 파일은 아래 순서입니다.

1. 싱크업 문서 또는 강의준비/기획 문서
2. 강의관리 시트
3. 만족도/설문 응답 시트
4. 결과보고서
5. 기타 Google Docs/Slides 참고 문서

템플릿 파일은 실제 운영자료가 아니므로 링크 후보와 본문 읽기 후보에서 제외합니다.
다만 새로 만들어가기 시작한 과정 폴더는 템플릿만 들어 있을 수 있으므로, 템플릿 파일만 있다는 이유로 폴더 후보 자체를 감점하지 않습니다.

## 필드 매핑

| 원천 | 상세페이지 후보 | 적용 방식 | 신뢰도 기준 |
| --- | --- | --- | --- |
| Drive 폴더 | `driveLink` | 교체 | 높음 |
| 싱크업/준비 문서 | `operationDetail` | 교체 | 높음 |
| 강의관리 시트 | `lectureManagementLink` | 교체 | 높음 |
| 결과보고서 | `resultReportLink` | 교체 | 보통 |
| 패들렛 | `padletLink` | 교체 | 보통 |
| 싱크업 문서 | `region`, `educationDays`, `timeText`, `instructors` | 교체 | 보통 또는 검토 |
| 싱크업/계약 관련 문서 | `instructorCost`, `operationCost`, `totalCost` | 교체 | 검토 |
| 만족도 응답 | `avgSatisfaction`, `instructorSatisfaction` | 교체 | 보통 |
| 만족도 응답 | 만족도 세부 메모 | `specialNotes`에 추가 | 검토 |
| 강의관리 시트 | 운영 이슈 | `operationIssue`에 추가 | 검토 |
| 강의관리 시트 | 운영진 의견 | `omUpdate`에 추가 | 검토 |
| 강의관리 시트 | 강의요약/현장 메모 | `specialNotes`에 추가 | 검토 |

기업명과 과정명은 폴더명/문서에서 추출되더라도 1차 구현에서는 참고 후보로만 표시합니다.
이미 운영 건에 있는 식별 정보를 자동으로 바꾸면 잘못된 폴더 연결 시 영향이 크기 때문입니다.

## 만족도 처리

만족도 응답은 과정 회차 수와 응답 시트 수가 반드시 일치하지 않습니다.
첫 회차와 마지막 회차만 조사하거나 일부 차수만 조사하는 경우가 있으므로, 응답 건수 자체를 오류로 보지 않습니다.

추출 기준:

- 전반 만족도 문항이 있으면 `avgSatisfaction` 후보로 사용합니다.
- 강사 만족도 전용 문항이 있을 때만 `instructorSatisfaction` 후보를 만듭니다.
- 강의 난이도, 강의 속도처럼 세부 만족도는 `specialNotes` 후보에 근거 메모로 남깁니다.
- 강사 만족도 전용 문항이 없으면 값을 만들지 않고, 메모에 별도 문항이 없음을 남깁니다.
- 만족도 후보는 파일명 또는 경로가 `만족도`, `설문`, `응답`, `결과보고` 원천임을 보여주는 파일에서만 만듭니다.
- 강의관리 시트 안의 `사후 만족도 문자 예약`, `설문 링크`, `만족도 링크` 같은 운영 체크리스트 행은 만족도 점수 원천으로 쓰지 않습니다.
- fallback 텍스트 추출은 `전체/전반/평균/종합 만족도`처럼 점수 행임이 드러나는 경우에만 허용하고, 0점 체크리스트 값은 제외합니다.

## 강의관리 시트 처리

강의관리 시트는 현장 운영 기록의 핵심 원천입니다.
자동 확정하지 않고 메모형 필드에 추가 후보로 제안합니다.
강의관리 시트는 만족도 점수 원천으로 사용하지 않습니다.

주요 추출 대상:

- `특이사항`, `이슈`, `장애`, `문제` 열은 `operationIssue` 후보입니다.
- `운영진 의견`, `운영 의견`, `운영 메모`, `OM 업데이트` 열은 `omUpdate` 후보입니다.
- `강의요약`, `수업요약`, `강의 내용` 열은 `specialNotes` 후보입니다.
- 강사명은 파일명 또는 `강사`, `강사명`, `강사님` 라벨이 분명한 행에서만 후보로 만듭니다.

빈 값, `없음`, `해당없음`, 헤더 반복값은 제외합니다.
`시계`, `시간`, `일정`, `장소`, `미팅`, `로그`처럼 강사명이 아닌 운영 단어도 제외합니다.

## 자동 검색 설계

폴더 URL이 없는 운영 건은 아래 순서로 검색합니다.

1. 기업명, 과정명, 시작월/종료월로 Drive 폴더 검색 쿼리를 만듭니다.
2. 폴더명에서 월 범위, 기업명, 과정명 토큰을 파싱합니다.
3. 기업명이 맞지 않는 폴더는 감점하고 상세페이지에서 흐리게 표시합니다.
4. 후보 폴더의 하위 폴더도 실제 과정 폴더 후보로 평가합니다.
5. 소유자 표시명이 OM 또는 LD와 일치하면 점수를 올립니다.
6. `★NEW TEMPLATE` 같은 양식 파일은 상세 후보에서 제외하되, 양식 파일만 있는 폴더도 폴더명/기업명/기간/담당자 기준으로 평가합니다.
7. 상위 후보를 상세페이지에서 보여주고 사용자가 선택합니다.
8. 선택된 폴더는 기존 Drive scan/apply 흐름으로 상세 후보를 생성합니다.

초기에는 자동 적용하지 않고 후보 선택 방식으로 시작합니다.
폴더 오매칭은 비용, 만족도, 이슈 기록까지 잘못 채울 수 있어 영향이 큽니다.
자동 검색이 애매하면 잘못된 폴더를 선택하지 않고 "찾지 못함"으로 멈추는 쪽을 우선합니다.

## 완료 기준

Drive 운영 상세 보강을 완료했다고 보기 위한 기준은 아래와 같습니다.

- 폴더 URL이 있는 운영 건에서 후보 생성과 선택 적용이 동작합니다.
- `.xlsx` 싱크업 문서도 텍스트를 읽어 후보를 만들 수 있습니다.
- 템플릿 파일은 후보로 뜨지 않습니다.
- 만족도 응답의 전반/강사/난이도/속도 문항을 구분합니다.
- 강의관리 시트의 운영 이슈와 OM 업데이트를 메모형 후보로 만듭니다.
- 폴더 URL이 없는 운영 건에서 Drive 검색 후보를 만들 수 있습니다.
- 후보 폴더 선택 전에는 운영 데이터를 자동 변경하지 않습니다.
- 선택된 후보값만 DB 저장 API를 통해 운영 건에 반영합니다.
