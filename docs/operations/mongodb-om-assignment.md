# OM 전체 배정의 Mongo 경계

OM 요청의 미리보기와 확인 후 배정·변경·취소를 명시 `omAssignment` repository로 연결한다. 운영 기본은 기존 PostgreSQL이다. 헤더·쿠키·요청 본문이나 새 환경변수로 Mongo를 선택하지 않는다. 구현·검증 진행 상태는 `.claude/plans/mongodb-om-assignment/` 실행 기록을 따른다.

## 보존하는 사용자 동작

미리보기에서 해당 요청 접수 시 생성된 연결 회차와 현재 담당자를 확인한다. 같은 과정에 나중에 추가한 회차는 자동 포함하지 않는다. 생성 감사의 requestId/route/method/action/targetType/targetId만 사용하며 개인정보 changes 값으로 연결을 추정하지 않는다. 요청 생성 근거 중복·누락, 서로 다른 요청이 섞인 배치, 회차 수·일정 불일치, 대표 회차 누락·삭제는 기존대로 409로 거절한다.

확인하면 연결 회차의 수동 담당자 이름과 계정 지정도 모두 교체한다. 취소하면 둘 다 비운다. 배정필요와 배정예정의 기존 전이만 적용하며 완료 상태는 유지한다. 선택 OM 이름은 기존 자유 입력 계약을 유지한다. 요청의 담당자가 같더라도 회차의 수동 값이 다르면 필요한 회차를 수정한다.

10분 확인 토큰은 기존 canonical 값과 HMAC을 사용한다. 로그인 주체·선택 담당자·요청의 8개 필드·회차의 7개 필드에 묶는다. 생성 배치 자체를 새로 서명하거나 요청의 모든 변경 이력을 추적하는 정책을 추가하지 않는다. 확인 저장 때 연결 조건과 최신 서명을 다시 검사한다. 응답은 no-store이며 이름을 URL에 넣지 않는다.

## 원자성과 동시 실행

요청·회차·변경 감사는 같은 Mongo 트랜잭션에서 저장한다. 변경할 행만 쓰는 snapshot 트랜잭션으로는, 두 배정이 서로 다른 회차를 변경하는 경우와 전체 복원 계획을 읽고 일부 회차만 옮기는 과정명 복원과의 역의존을 막지 못한다.

이를 위해 **기존 `CourseNameRestoreGuard`의 같은 `restore` 문서**를 배정 confirm도 사용한다. 새 업무 필드·마이그레이션·새 collection 계약·의존성을 추가하지 않는다. 매 시도는 같은 session/transaction에서 새 nonce를 쓴 뒤 요청·생성 근거·회차를 읽고 서명을 검사한다. 기존 과정명 복원도 이미 이 보호 지점을 사용한다. preview는 이 문서를 쓰지 않는다.

전체 값이 같으면 업무 문서·업무 시각·변경 감사는 그대로이고 내부 guard의 nonce만 바뀐다. 개인정보를 잠금 목적으로 재암호화하지 않는다. 일반 요청·회차 쓰기나 감사 보존 기간 정책에 근거 없이 공통 잠금을 추가하지 않는다. 같은 문서 충돌은 최신 재시도로, 단방향 의존은 유효한 직렬 실행 순서로 판정한다. 생성 감사 전체에 대한 predicate 잠금이라고 해석하면 안 된다.

전체 대기·재시도·commit 확인 예산은 30초다. 최초 guard upsert의 중복 분기는 최초 포함 최대 5회이며, 실제 transient 오류는 driver가 전체 callback을 재시도한다. commit 결과가 불명확하면 driver의 commit 확인을 따르고 업무 callback이나 외부 알림을 임의 재실행하지 않는다. 마지막 결과를 확정하지 못했을 때 롤백 완료로 안내하지 않는다.

명시 prepare에서 기존 validator/index와 기존 guard를 준비한다. 준비된 guard collection의 최초 문서 upsert는 허용하지만 open이나 업무 호출이 collection을 자동 생성·수리·삭제하지 않는다. 생성 감사 metadata는 100행 단위의 정렬된 조회로 읽고 15초·2만 행·32MiB 한도를 지킨다.

## 권한·외부 반영·한계

실제 세션 이메일과 기존 파트 관리자 명단의 유일성, 기존 명시 override를 preview와 PATCH에서 각각 확인한다. 표시 이름만으로 권한을 부여하거나 일반 admin 역할에 새 배정 권한을 추가하지 않는다. 권한 검사와 DB 트랜잭션의 분리는 기존 한계로 남는다.

확인 저장 전에 필요한 operations/calendar/notifier 포트를 확인한다. 명시 context에서 누락되면 기본 PostgreSQL·파일·실제 외부 서비스로 대체하지 않는다. 커밋 후 변경된 회차만 캘린더에 반영하고 기존 조건을 충족할 때만 Slack에 알린다. 외부 실패는 업무 저장을 되돌리지 않으며 예외 원문을 로그에 남기지 않는다. HTTP 요청 로그와 기존 retention은 별도 best-effort다.

기존 확인 없는 request-only 배정 helper와 같은 과정 전체를 동기화하는 helper는 명시 scope에서 계속 차단한다. 검증된 preview/confirm 경계만 연다.

같은 namespace의 무관한 배정과 과정명 복원도 guard에서 경쟁한다. 운영 처리량·실제 네트워크 단절·실제 로그인·외부 전송·브라우저 E2E·운영 데이터 복사/복원/최종 전환은 별도 검증이다. 이 기능 경계가 전체 Mongo 이전이나 운영 개인정보 암호화 완료를 뜻하지 않는다.
