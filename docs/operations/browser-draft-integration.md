# 로그인 기반 브라우저 초안 통합

## 확정한 사용자 동작

2026-09-21 별도 초안 암호 없이 기존 Google 로그인을 사용하는 방식을 선택했다. 이미 로그인하고 초안 키를 받은 열린 화면은 인터넷 또는 앱 서버 장애 중에도 브라우저에 암호문을 저장한다. 새로고침·탭 종료·브라우저 재시작으로 메모리 키가 사라지면 온라인에서 같은 계정으로 인증한 뒤 복구한다. 장애 중 재시작 직후 복구는 이 방식의 보장 범위가 아니다.

암호문은 작성한 브라우저의 IndexedDB에 남는다. 다른 기기로 동기화되는 서버 초안 보관 기능은 아니다. 브라우저 데이터 삭제·장치 분실·저장 용량 부족·비공개 브라우징 종료로 인한 데이터 손실을 막는 백업도 아니다. 앱 화면 자체의 오프라인 재시작을 위한 Service Worker는 추가하지 않는다.

## 적용 범위

| 경로 | 보존 대상 | 정상 저장 전제 |
| --- | --- | --- |
| 강의관리 | 메모 탭·링크·편집 모드 | 본인 키 수령 및 암호문 저장소 준비 |
| 운영 이슈·회고 | 특이사항·운영 이슈·OM 업데이트 | 기존 암호문 읽기 성공 후 편집 시작 |
| Drive 가져오기 | 검색·스캔 결과와 선택·수정 값 | 기존 암호문 읽기 성공 후 편집 시작 |
| 신규 운영 등록 | 등록을 시작한 요청의 본문·회차 순서·재시도 식별자 | 첫 서버 요청 전에 암호문 저장 commit 완료 |

신규 운영 등록은 등록 시작 시점의 재개 정보 보존이다. 등록 버튼을 누르기 전 모든 입력을 실시간 저장하는 기능을 추가한 것은 아니다. 재개 시 동일 요청 식별자를 사용하여 응답 유실로 이미 등록된 회차를 다시 만들지 않는다.

같은 계정의 두 탭이 동시에 등록을 시작하면 먼저 저장한 재개 정보를 보존한다. 조회 당시 암호문이 달라진 경우 한 IndexedDB 트랜잭션 안에서 저장·삭제를 거부한다. 신규 등록 요청은 기대 Google 계정과 서버의 실제 로그인 계정도 비교하므로 전송 직전 계정이 바뀌면 쓰기 전에 거부한다.

## 계정 경계 및 키

서버 전용 키에서 인증된 Google 계정별 키를 파생한다. [서버 키 설정과 회전](browser-draft-server-keys.md)을 따른다. 키는 브라우저 메모리에만 유지하고 영구 저장소에는 암호문과 불투명한 소유자 범위만 기록한다. 로그아웃과 계정 변경 때 열린 초안과 키를 잠근다. 단순한 네트워크 실패는 로그아웃으로 처리하지 않는다.

오프라인인 동안 원격 권한 회수 사실을 즉시 확인할 수는 없다. 이때 기존 열린 탭의 편집을 유지하는 것이 선택한 동작이다. 같은 브라우저 프로필을 타인에게 넘길 때는 로그아웃해야 한다. 저장 암호화는 잠금 해제된 화면을 다른 사람이 보거나 동일 origin 악성 코드가 실행되는 공격을 막지 않는다.

## 기존 평문 초안: 암호화 격리 전환 승인

기존 세 가지 초안 형식에는 검증 가능한 작성자 정보가 없다. 기존 신규 등록 재개 정보의 클라이언트 식별자 역시 소유권 인증이 아니다. 현재 로그인한 계정에 자동 귀속하거나 원문을 화면에 표시하지 않는다. 전환을 실행한 로그인 계정은 초안 소유자를 뜻하지 않는다.

2026-09-21 사용자가 **암호화 보존 → 실제 저장된 사본의 복호화 일치 검증 → 안전 조건 확인 후 평문 제거**를 승인했다. 별도 초안 암호나 관리자 소유 확인을 도입하지 않는다. "관리자가 작성자를 확인해 복구한다"는 이전 제안은 확인 근거가 없어 철회했다. 작성자 미확정 옛 초안은 일반 계정에 자동 복구하지 않는다.

전환의 실행 조건과 검증은 [옛 초안 격리 전환](legacy-draft-quarantine.md)을 따른다. 전환 코드의 완성과 운영 브라우저에 남은 실제 평문의 제거는 별도 상태다. 사용자가 방문하지 않은 브라우저·탭·프로필의 데이터까지 제거됐다고 보고하지 않는다.

## 통합 검증 기준

- 실제 서버 파생 응답을 클라이언트가 수용하고 계정별 암호문을 분리한다.
- 열린 탭의 네트워크 장애 중 저장, 키 없는 재시작의 잠금, 온라인 동일 계정 복구를 구분한다.
- 로그아웃·다른 탭 계정 변경·늦게 도착한 응답이 이전 초안을 표시하거나 다른 계정으로 저장하지 않는다.
- 암호문 손상·알 수 없는 키·저장 용량 오류 시 기존 사본을 유지하고 실패를 알린다.
- 신규 등록은 암호문 commit 전에 네트워크를 시작하지 않고, 첫 회차/후속 회차 응답 유실 후 동일 요청으로 재개한다.
- 프록시의 내부 주소와 공개 Origin이 다른 경우에도 신뢰 설정에 따라 정상 요청만 허용한다.
- 테스트는 합성 계정·데이터로 수행한다. 실제 Google 로그인, 운영 Coolify, 운영 PostgreSQL, 실제 키 설정은 별도 배포 전 검증 대상이다.

## 운영 반영 조건

별도 DB 스키마나 의존성을 추가하지 않는다. 기존 PostgreSQL 사용을 유지하며 MongoDB 이전 실행과 분리한다. 인증/API 변경이므로 기술 책임자의 검토, 전용 키의 보관·복구 책임자 지정, 공개 Origin 설정, 승인된 옛 초안 전환 절차의 검증을 마친 뒤 반영한다. 로컬 구현·테스트 결과는 배포 완료를 뜻하지 않는다.

## 로그인 기반 초안 통합 검증 기록 (격리 전환 추가 전)

2026-09-21 통합 작업 브랜치에서 Node 24.19.0과 기존 잠금 파일의 의존성을 사용했다. DB 주소는 접속할 수 없는 로컬 합성 주소로 지정했으며 운영 DB에 접속하지 않았다.

- `npm test`: 680개 통과, 실패 0개, 격리 PostgreSQL이 필요한 4개 생략.
- `npm run typecheck`: 통과.
- `npm run build`: 통과.
- `npm run lint`: 오류 0개, 기존 무관한 경고 7개.
- 독립 코드 검토: 서버 Origin 판정, 계정 전환 렌더 경계, 지연 저장의 세대 검사, 단일 트랜잭션 안의 다중 탭 CAS와 신규 등록 연결을 보완 후 재검토했다.

생략한 DB 검증은 활동 기록 트리거·과정명 복원·동시 실행 잠금·PII 마이그레이션의 실제 PostgreSQL 통합 검사다. 모의 트랜잭션과 단위 테스트 통과가 실제 PostgreSQL 경합 검증을 대신하지 않는다.

실제 제품 컴포넌트·Provider·WebCrypto·브라우저 IndexedDB를 사용하는 합성 브라우저 검증도 통과했다. 로그인·업무 API·라우팅은 모의 환경이다. [세 편집기와 다중 탭 검증](browser-draft-product-evidence.md), [신규 등록의 응답 유실 및 재개 검증](operation-submission-browser-verification.md)에 관찰 근거와 한계를 기록했다. 세 폼의 서버 종료 중 저장·같은 계정 복구·다른 계정 비노출, native IndexedDB 충돌 방지, 신규 등록의 동일 요청 재시도를 확인했다. 문서 재로드와 새 runtime 검증이며 브라우저 프로세스 완전 종료나 OS 재시작 검증은 아니다.
