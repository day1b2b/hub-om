**부모의 큰 limit P2 수정은 정적으로 수락합니다.**

- `MAX_SAFE_INTEGER` 이하는 `take` 유지.
- 그보다 크고 `2**63` 미만인 합법적 limit는 `take` 생략.
- `2**63` 이상은 고정 오류로 거부.
- PG/native 양쪽에서 같은 helper를 사용합니다.
- `limit-probe.log`의 성공 3건과 `22003` 2건도 위 경계와 일치합니다.

읽은 native 코드에서는 새로운 구체적 차단 결함을 발견하지 못했습니다. 전체 모델 선검증 후 prepare, 단일 snapshot 조회, 재시도 밖 ID·직렬화·암호화, append 부모 확인, finish의 제한된 `$set`은 계약에 부합합니다.

**최종 판정은 완료된 부모 수정 범위에 한정합니다.** native는 진행 중이므로 최종 수락하지 않았으며, 예정된 세 backend limit 회귀 결과도 아직 미확인입니다. DB·테스트 실행·파일 수정은 없습니다.
