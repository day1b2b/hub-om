# 읽기 전용 조사

Carver: CLI는 env→PGconnect→legacyguard→운영innerjoin조회→pendingrun→병렬source/개별result→summary완료 순서. 전체transaction없음. source/mapping/insert가같은catch로오류result에재기록되고그쓰기까지실패하면pending부분results가남는다. candidateCount는전체이고저장key는6field/검색후보top10,집계는INSERT전증가. scannerissues-only는errors0/completed가능. package실행진입점과Docker포함은확인,repo예약연결없음/외부예약미확인. 기존Drive조회는재구현비대상.

Volta: migration4(20260614190000_add_drive_import_runs)에서Drive테이블과uuiddefault생성, migration7제거,9복원,17(20260713150000_add_team_user)까지기능schema,18(20260723062051_add_coach_day_reservation)재제거,42privacy부터guard가먼저차단. 현재schema에테스트용default복원/guard우회금지.

부모선택: 정당한migrationprefix17로기능oracle, prefix18의별도DB로SQLSTATE23502/guard통과후INSERT실패gate, 현45migrationDB로guard차단/source0/write시도0gate를분리한다. migrationprefix는원문순서·hash·actualdefault/FK로검증한다. baseline원본을역사schema에서실행한기능oracle이며과거실제운영배포재현이라고부르지않는다. 원본코드와실제guard는변경하지않고env없는합성cwd에서만실행한다.

예정새소유PG56753 아래drive_writer_test/current, drive_writer_legacy/prefix17, drive_writer_no_defaults/prefix18. Mongo27853/drivewriter20260930. 아직생성/실행없음. 작업root /private/tmp/hub-om-drive-writer-20260930 예정. 제품수정없음.

Meitner: load는한snapshot에서innerjoin/정렬후limit, append는source/가공/집계밖의짧은transaction과고정ID, finish는원자$set. 실제append commit 후ACK최종오류이면원본catch가별도errorresult를써서성공+오류2행가능하며unique/중복제거금지. source/집계횟수는retry밖에유지. operation날짜NOTNULL/결과날짜nullable구분. PG DATE의로컬TZ파싱+dateOnly UTC변환을UTC/AsiaSeoul원본gate로먼저관찰; 새code에서임의수정하지않는다. concurrency0.5는floor후0workers; confidence기본없음/evidence만빈문자열; SQL status소문자와Prismaenum대문자변환; SQLNULL/JSON/[]구분.

native부모존재확인만으로물리삭제와동시FK보장안됨. 현재nativeOperationSession은softdeletewriter만검색확인했고DriveRun물리삭제제품경로는확인되지않았다. 새로운물리삭제/guard정책없이이번scope의부모존재·softdelete/concurrentappend만검증하고물리삭제와동시CASCADE/SETNULL동등성은주장하지않는다. 전체runtime구성/삭제경로후속점검gate에남긴다.

prepare는DriveHistory와같이5모델전체기존상태를먼저검증하고누락모델만만들어야한다. 기존metadata/invaliddocuments/crypto/HMAC은분리검사,namespace자동수리금지. PG withActivity wrapper는activitycontext없는CLI에서추가감사쓰기없음을테스트로확인한다.

Sagan: env파일은기존환경도덮어쓰는 .env→.env.local 순서. source저장소키오류와Google설정누락issues를구별한다. Google전역token cache는credential별아니고동시coldOAuth1회보장없음; 고정합성설정A/B, 설정행렬별도worker. URL에서추출한folderId는OAuth/metadata실패의catch에도남아 scan_found_folder+issues+errors0가능. 검색HTTP비정상JSON정상은빈query, JSON/fetch오류는바깥issues; 문서HTTP실패빈본문과rejection전체scan실패구별. transport assertion은scannercatch에삼켜지므로별도위반수집/호출즉시기록+종료시반드시확인. source비Error String변환(toString자체실패포함)과repository고정code변환분리. existing scanner직접unit은찾지못했으므로검증재사용증거로계산하지않는다. 새actualHTTP연결검증이필요하다.
