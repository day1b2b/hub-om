# 검증 기준
구조: Core 단계 존재, 후보 완화 규칙·상한·저장 정책 명시. 구조 실패 시 결과 기준 평가 금지.

## 정확성 (5)
1. 전체 20,001행 이상에서 업무 조건으로 2행 후보 축소, 평문 참조 결과 일치.
2. AND와 ID 조건 유지.
3. OR의 개인정보 전용 분기는 후보 전체 OR를 완화하고 최종 결과 유지.
4. 보호 조건 포함 NOT 전체를 후보에서 제외하여 누락 방지.
5. 복합 개인정보 조건의 AND/OR 의미 유지.

## 보안과 자원 (5)
1. 검색은 필요한 암호문만 조회; 정렬은 PK/정렬키만 조회.
2. 정확 일치는 HMAC, scan 없음.
3. 20,000행 성공/20,001행 오류; byte 상한 초과 오류.
4. 결과 잘림·무제한 복호화·상한 증가 없음.
5. 쿼리/오류에 평문 검색어·토큰·키 없음; 파일 손상 시 fallback 금지.

## 회귀와 정직성 (5)
1. mock은 where를 실제 평가, 반환 ID를 독립 평문 기대와 비교.
2. contains/startsWith/endsWith/insensitive/null 경계 확인.
3. 정렬 skip/take/보조정렬/상한과 projection 보존.
4. CLI dry-run 쓰기 없음, apply 암호화 경유 및 최신 유효 토큰 선택.
5. DB 없는 검증을 실제 PostgreSQL/화면/키 복구 검증으로 대체 주장하지 않음.

메타 검토: 사용자 요구→위 3범주 전부 추적됨. 후보 축소의 누락 반례(NOT), 보안 누출 반례(평문 query), false pass(mock where 무시)를 실패 조건으로 명시. 브라우저 정책은 사용자 결정 대기이므로 코드 변경 합격 기준 밖, 전체 목표의 미해결 항목으로 유지.
