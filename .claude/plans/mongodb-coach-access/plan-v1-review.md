# 독립 계획 검토
구조 S1–S3 통과. Core는 token본인조회/export/재발급, Shell은 명시 context, Check는 handler/native 반례로 추적 가능하다. 기존 PG 기본값을 보존하는 경계 추출은 전면 전환보다 현재 미전환 경로 위험을 제한한다. 제품 코드 수정 없이 현재 route를 읽어 검토했다.

실행 전 명확화할 두 계약:

1. export의 '선택순서 유지'는 실제 기존 코드의 normalizedName ascending과 다르다. 입력 순서 보존을 새로 도입하지 않고 기존 이름 정렬 유지로 정리한다.
2. 재발급의 삭제 코치 거절은 기존 PG where id-only 동작과 다르다. 의도된 보안 개선으로 문서화하고 no-context PG에도 동일하게 적용할지 총괄이 정한다.

CSV는 기존 double quote escaping만으로 =/+/-/@ 수식 실행을 막지 못한다. 이 단계에서 개선한다면 사용자 CSV 값 변환 계약과 반례를 명시하고, 보류하면 보안 gap을 숨기지 않는다. 위 내용을 총괄에 즉시 전달했다.

validation-v2는 단순 token 존재 인증, blind-index만 신뢰, 최신 미완료 archive 오선택, 후행 PII 감사 batch 실패, token/index/변경감사 부분 저장, 동시 재발급의 복수 유효 토큰 오주장을 반례로 삼는다. 기존 수식 문제 외 아직 새 제품 구현의 확정 버그를 주장하지 않는다. 이번 검토는 결과 통과가 아니라 계획 검토이며 실제 구현·실행은 별도 review가 필요하다.


총괄 결정 반영: 이름 정렬 유지, 삭제/없는 코치 재발급 404를 양 backend에 적용하는 보안 개선, CSV 수식 방지 접두 변환을 이번 범위로 확정했다. 정당한 +전화번호도 문자열 접두가 추가되는 변화이며 quote/BOM/열 계약은 유지한다. validation-v2에 공백 뒤 수식·제어문자·전화번호 반례와 진행 중 인증의 소급 취소 한계를 추가했다. 위 열린 계약은 해소되어 계획 검토 통과다.
