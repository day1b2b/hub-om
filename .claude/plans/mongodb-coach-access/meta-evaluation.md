# 검증 기준 메타 검토
구조 S1–S3 통과. v1에는 다음 거짓 통과 위험이 있어 v2에 반례를 보강한다.

- token 단순 존재 또는 blind index만 일치해도 인증하는 구현: ciphertext/AAD/index 변조·다른 코치 토큰 교환과 정확값 비교가 필요하다.
- 삭제코치 재발급 차단은 현재 PG의 동작 개선이다. 기존 의미를 보존했다는 주장과 분리하고 양 backend 정책/HTTP 결과를 확정한다.
- export 입력순서와 기존 normalizedName 정렬은 다르다. 실구현 기준으로 정렬을 명시한다.
- 감사 batch의 첫 행에서만 오류를 내면 일부 감사 원자성을 놓친다. 두 행 중 후행 감사 실패로 검증한다.
- 토큰 재발급 실패·동시 재발급·삭제와 경쟁, 변경 감사에서 원문 token 누출을 검사한다.
- CSV quote escaping은 수식 평가 방지가 아니다. 기존 수식 선두 값을 별도 보안 gap 또는 명시 개선으로 정해야 한다.
- request 감사는 best-effort여도 PII 접근/변경 감사는 failclosed다. 기록 종류를 혼동하지 않는다.
