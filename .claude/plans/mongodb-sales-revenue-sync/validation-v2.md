## Validation v2 — 최종 명세

**계획 검증용 명세다. 제품 실행 검증 PASS를 의미하지 않는다.** 숫자 probe와 NaN/±Infinity의 SQL NULL 확인은 사용자 제공 완료 사실로 반영한다. 원본의 누적 overflow→null 계약도 유지하며 새 거부 정책을 추가하지 않는다.

구조 게이트는 다음과 같다.

- **S-1:** 모든 단계에 Core/Shell/Check 태그가 있어야 한다.
- **S-2:** Core가 1개 이상이어야 한다.
- **S-3:** Core마다 입력·조건·변환·출력·실패 경계가 결정되어야 한다.
- **하나라도 FAIL이면 결과 품질 채점 금지.** 아래 테스트는 구조 통과 후 적용한다.

### 요구사항 → 기준 → 테스트 추적

| 요구사항 | 검증 기준 | 필수 테스트 |
|---|---|---|
| **R1 원본 계산** | **V1 원본 응답·금액·순서 보존** | **T11** 상태별 preview/apply·부작용, **T12** 필터·정규화·resolution 충돌·다중 딜·복수 Course·중복, **T13** decimal 경계·비유한값·재실행, **T14** 중복 제거·pending 재계산 방지, **T15** 허용 필드에 한정한 순서 차이 |
| **R2 원자성·경합** | **V2 snapshot 고정·최신행 감사·원자성** | **T21** 수동필드 writer 양방향, **T22** pending 이후 이미 목표값, **T23** same 이후 수동 변경·신규 매칭 한계, **T24** 중복 pending 중간 경합·재시도, **T25** 업무/변경감사 rollback·별도 로그 실패 |
| **R3 외부/API/보안** | **V3 실제 route·scope 격리·비노출** | **T31** 인증·HTTP·POST 파싱, **T32** cron 알림 조건·요청 감사, **T33** 필수 4port 각각 누락, **T34** 오류 치환·정상 preview 유지, **T35** 암호화·키 손상·AAD 실패 |
| **R4 검증·인계** | **V4 독립 증거·전체 검증·범위 준수** | **T41** 동결 oracle·SHA·probe 증거, **T42** 전체 test/Mongo/실제 합성 DB·handler/type/lint/build·독립 리뷰, **T43** 중복 집계·동일 결과 재사용, **T44** skip/미실행 허위 통과 방지, **T45** 자원 소유·금지 변경·원격 SHA·인계 |

필수 분모는 **20개 테스트와 각 테스트의 열거된 하위 사례 전부**다. T1~T4 묶음은 각각 T11~T15, T21~T25, T31~T35, T41~T45에 대응한다.

### 합격 임계값

- **V1:** 허용 차이 외 응답·저장·카운터 차이 **0개**, 금액 오차 **0**. 원본/newPG/Mongo를 독립 oracle로 비교한다.
- **V2:** 부분 업무·변경감사 잔존 **0건**, 무관 필드 손실 **0개**, 재시도로 추가된 감사 **0건**. 원본 중복 pending은 제거하지 않는다.
- **V3:** 명시 scope의 기본 PG·실원천·실Slack 접근 시도 **0회**, 보호 대상 평문·오류 원문 노출 **0건**, 실패 시 평문 fallback **0회**.
- **V4:** 요구사항·테스트 미연결 **0개**, 필수 증거 누락·미해결 실패·필수 skip/미실행 **0개**, 금지 자원 변경 **0건**.

허용 차이는 **안전 오류 치환**, **source 구간별 복수 Course multiset 및 첫 매칭행의 표시 이름 두 필드**, **신규 생성 UUID·시각 정규화**뿐이다. 기존 fixture 식별자·시각과 source/pending 순서는 유지한다.

경합 기대값은 고정한다.

- **same 이후 수동 변경:** pending 추가 없음, 수동값 유지, 기존 same 응답 유지.
- **pending 이후 이미 목표값:** pending 실행·updatedRows 유지. revenue/raw가 같으면 시각만 변경되어 변경감사는 없음.
- **중복 pending 경합:** 최초 순서·중복·카운터 유지. 감사는 각 실제 쓰기 직전 행 기준이며 실패한 시도의 감사는 남지 않는다.
- 조회 이후 신규 Course·매칭 진입은 기존 한계다. 새 즉시 일관성·수동매출 우선권을 요구하지 않는다.

**실행 상태:** 제품 검증은 미착수다. 테스트 합격 점수는 산출하지 않는다.
